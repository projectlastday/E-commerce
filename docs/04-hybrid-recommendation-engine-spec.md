## 1. Hybrid Recommendation Taxonomy & Strategy Rationale

### 1.1. Theoretical Framework: Robin Burke (2002) Taxonomy
In *Hybrid Recommender Systems: Survey and Experiments* (Burke, 2002), seven hybridization paradigms are classified:
1. **Weighted**: The scores of several recommendation techniques are combined mathematically.
2. **Switching**: The system switches between recommendation techniques depending on criteria (e.g. data density).
3. **Mixed**: Recommendations from different recommenders are presented together side-by-side.
4. **Feature Combination**: Features from different knowledge sources are combined into a single recommendation algorithm.
5. **Cascade**: One recommender refines the candidates generated by another (staged pipeline).
6. **Feature Augmentation**: One technique produces a rating or classification, which is then fed as a feature into another.
7. **Meta-level**: One recommender produces an entire model that is used as input for the next.

### 1.2. UMKM Selection: Cascade Candidate Generation + Switching-Weighted Ranking
For this UMKM e-commerce architecture, we design a **Two-Stage Hybrid Engine**:
- **Stage 1 (Retrieval / Candidate Generation)**: **Mixed & Cascade**. Multiple fast retrievers run concurrently (pgvector semantic search, implicit ALS collaborative retrieval, and category trending) generating a combined pool of $M \approx 100$ candidate items.
- **Stage 2 (Scoring & Ranking)**: **Switching-Weighted Blending**. The ranking score combines Collaborative Filtering (CF) and Content-Based Filtering (CBF), where the weights dynamically **switch** based on the user's interaction count (Cold-Start vs. Warm Profile).
- **Stage 3 (Post-Processing & Diversification)**: **Maximal Marginal Relevance (MMR)** and business rule constraints (inventory filtering, frequency capping).

## 2. Content-Based Filtering (CBF) Mathematical Specification

### 2.1. Text Representation & Embedding Pipeline
For each product $i$, metadata is serialized into a structured contextual string:
$$\text{Document}(i) = \text{Title} \parallel \text{" | Kategori: "} \parallel \text{CategoryPath} \parallel \text{" | Deskripsi: "} \parallel \text{CleanDescription} \parallel \text{" | Atribut: "} \parallel \text{AttributesJSON}$$

The string is projected into a dense vector space $\mathbf{e}_i \in \mathbb{R}^{384}$ using `paraphrase-multilingual-MiniLM-L12-v2`:
$$\mathbf{e}_i = \frac{\text{Encoder}(\text{Document}(i))}{\|\text{Encoder}(\text{Document}(i))\|_2}$$

### 2.2. Dynamic Real-Time User Profile Vector
A user's semantic preference vector $\mathbf{u}_e \in \mathbb{R}^{384}$ is maintained dynamically in Redis and updated upon every interaction event $e \in E_u$:

$$\mathbf{u}_e = \frac{\sum_{i \in H_u} r_{ui} \cdot \mathbf{e}_i}{\left\|\sum_{i \in H_u} r_{ui} \cdot \mathbf{e}_i\right\|_2}$$

Where:
- $H_u$ is the historical sequence of items interacted with by user $u$ within the active observation window (default: last 30 interactions).
- $r_{ui}$ is the time-decayed interaction weight defined in SPEC-DOC-001.

### 2.3. Semantic Similarity Metric
The content similarity score between user profile $\mathbf{u}_e$ and candidate product $\mathbf{e}_i$ is the Cosine Similarity:
$$S_{CBF}(u, i) = \frac{\mathbf{u}_e \cdot \mathbf{e}_i}{\|\mathbf{u}_e\|_2 \|\mathbf{e}_i\|_2} = \mathbf{u}_e \cdot \mathbf{e}_i \quad (\text{since } \|\mathbf{u}_e\|_2 = \|\mathbf{e}_i\|_2 = 1)$$

> **Vector Execution with MySQL**:
> Since MySQL handles relational state, product embeddings are cached in-memory inside the Python RecSys service using **FAISS** (`faiss.IndexFlatIP` for inner product / cosine on normalized vectors) or NumPy dot products. For an SME catalog ($500 - 50,000$ SKUs), this in-memory index consumes $< 20\text{MB}$ RAM and computes top-50 nearest neighbors in $< 2\text{ms}$. Alternatively, MySQL 8.4+ native `DISTANCE(..., 'COSINE')` can be queried.

## 3. Collaborative Filtering (CF) Mathematical Specification

### 3.1. Implicit Alternating Least Squares (iALS)
Following **Hu, Koren, & Volinsky (2008)**, the interaction matrix consists of implicit observations $r_{ui} \ge 0$.

#### Binary Preference & Confidence:
$$p_{ui} = \begin{cases} 1 & \text{if } r_{ui} > 0 \\ 0 & \text{if } r_{ui} = 0 \end{cases}$$
$$c_{ui} = 1 + \alpha r_{ui}, \quad \text{with } \alpha = 40$$

#### Optimization Objective:
Minimize the penalized weighted squared error over user latent vectors $\mathbf{x}_u \in \mathbb{R}^f$ and item latent vectors $\mathbf{y}_i \in \mathbb{R}^f$ (with $f = 64$ latent dimensions):

$$\min_{\mathbf{x}_*, \mathbf{y}_*} \mathcal{L}_{ALS} = \sum_{u, i} c_{ui} (p_{ui} - \mathbf{x}_u^T \mathbf{y}_i)^2 + \lambda \left(\sum_u \|\mathbf{x}_u\|_2^2 + \sum_i \|\mathbf{y}_i\|_2^2\right)$$

Where $\lambda = 0.05$ is the $L_2$ regularization parameter.

#### Coordinate Descent Updates:
At each alternating iteration, while keeping item factors $Y \in \mathbb{R}^{M \times f}$ fixed, each user vector is solved analytically:
$$\mathbf{x}_u = \left(Y^T C^u Y + \lambda I\right)^{-1} Y^T C^u \mathbf{p}(u)$$

Exploiting the sparsity property $C^u - I$:
$$Y^T C^u Y = Y^T Y + Y^T (C^u - I) Y$$
Where $Y^T Y$ is precomputed once per iteration in $\mathcal{O}(f^2 M)$, reducing per-user update complexity to $\mathcal{O}(f^3 + f^2 |R_u|)$.

Collaborative prediction score:
$$S_{CF}(u, i) = \mathbf{x}_u^T \mathbf{y}_i$$

### 3.2. Hybrid Matrix Factorization (LightFM Formulation)
To bridge the gap between collaborative patterns and content features, **LightFM (Kula, 2015)** models user and item representations as linear combinations of their latent feature vectors:

$$\mathbf{p}_u = \sum_{g \in G_u} \mathbf{v}_g, \quad \mathbf{q}_i = \sum_{j \in F_i} \mathbf{w}_j$$

Where:
- $F_i$ includes item ID, category ID, price tier tag, and brand/merchant tag.
- $G_u$ includes user ID and onboarding preference tags.

The predicted ranking score is:
$$\hat{r}_{ui} = \mathbf{p}_u \cdot \mathbf{q}_i + b_u + b_i$$

Optimized via **WARP (Weighted Approximate-Rank Pairwise)** loss, which maximizes the precision at the top of the recommendation list by repeatedly sampling negative items until a violation is found.

## 4. Multi-Stage Recommendation Pipeline Specification

### 4.1. Stage 1: Candidate Generation (Retrieval)
1. **Semantic Candidate Retrieval ($C_{CBF}$)**:
   - Query pgvector index using user dynamic vector $\mathbf{u}_e$ with HNSW search:
   ```sql
   SELECT product_id, 1 - (embedding <=> :user_vector) AS cbf_score
   FROM product_embeddings
   ORDER BY embedding <=> :user_vector
   LIMIT 50;
   ```
2. **Collaborative Candidate Retrieval ($C_{CF}$)**:
   - For registered users, query the in-memory iALS model:
   ```python
   ids, scores = als_model.recommend(user_idx, user_items_sparse[user_idx], N=50, filter_already_liked=True)
   ```
3. **Popularity & Trending Retrieval ($C_{POP}$)**:
   - Query the top 20 trending items in user's top-2 most interacted categories over the past 7 days.
4. **Candidate Union**:
   $$\mathcal{C}_{total} = C_{CBF} \cup C_{CF} \cup C_{POP} \quad (|\mathcal{C}_{total}| \approx 80 \text{ to } 110 \text{ items})$$

### 4.2. Stage 2: Min-Max Normalization & Weighted Scoring
Because raw scores from iALS ($\mathbf{x}_u^T \mathbf{y}_i \in [-\infty, +\infty]$), pgvector cosine similarity ($S_{CBF} \in [-1, 1]$), and Trending ($S_{POP} \in [0, +\infty]$) operate on incompatible scales, scores are normalized within the candidate set:

$$\tilde{S}(x) = \frac{x - \min(X)}{\max(X) - \min(X) + \epsilon}, \quad \text{where } \epsilon = 10^{-6}$$

The unified hybrid score is:
$$S_{final}(u, i) = w_{CF} \cdot \tilde{S}_{CF}(u, i) + w_{CBF} \cdot \tilde{S}_{CBF}(u, i) + w_{POP} \cdot \tilde{S}_{POP}(i)$$

#### Dynamic Switching Policy:
Let $N_u$ be the number of confirmed interactions recorded for user $u$:
- **Case 1: Pure Cold-Start ($N_u = 0$)**:
  $$w_{CF} = 0.00, \quad w_{CBF} = 0.60, \quad w_{POP} = 0.40$$
- **Case 2: Early Interaction ($1 \le N_u < 5$)**:
  $$w_{CF} = 0.20, \quad w_{CBF} = 0.60, \quad w_{POP} = 0.20$$
- **Case 3: Mature Warm Profile ($N_u \ge 5$)**:
  $$w_{CF} = 0.55, \quad w_{CBF} = 0.35, \quad w_{POP} = 0.10$$

### 4.3. Stage 3: Maximal Marginal Relevance (MMR) Diversification
To prevent "filter bubble" redundancy (e.g. recommending 10 nearly identical navy t-shirts), candidates are diversified using Carbonell & Goldstein (1998) MMR:

$$\text{MMR} = \arg\max_{i \in \mathcal{C} \setminus \mathcal{S}} \left[ \lambda \cdot S_{final}(u, i) - (1 - \lambda) \max_{j \in \mathcal{S}} \text{Sim}(i, j) \right]$$

Where:
- $\mathcal{S}$ is the set of items already selected into the recommendation list.
- $\text{Sim}(i, j) = \mathbf{e}_i \cdot \mathbf{e}_j$ (Cosine similarity between item vectors).
- $\lambda = 0.70$ (Optimal trade-off parameter between relevance and diversity for e-commerce catalog exploration).

## 5. Comprehensive Cold-Start Solution

### 5.1. New User Cold-Start Strategy
```
                     [New Visitor Arrives]
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
       [Anonymous Guest]             [Newly Registered]
               │                               │
        Has Onboarding Tags?            Completed Onboarding Quiz?
        ┌──────┴──────┐                 ┌──────┴──────┐
       YES            NO               YES            NO
        │              │                │              │
        ▼              ▼                ▼              ▼
   Build Vector   Category Trend  Average Category  Sitewide Top-N
   from Selected  + Bandit (ε=0.2) Embeddings into  Trending Items
   Tags           Exploration      Initial Vector
```

1. **Guest In-Session Vectorization**:
   - As an anonymous visitor clicks item 1, the session vector in Redis is set to $\mathbf{u}_{session} = \mathbf{e}_1$.
   - On click 2, $\mathbf{u}_{session} = 0.4 \cdot \mathbf{e}_1 + 0.6 \cdot \mathbf{e}_2$. Immediate personalization begins by page 2 without registration.
2. **Multi-Armed Bandit ($\epsilon$-Greedy with Decay)**:
   - For visitors with zero history, $1 - \epsilon$ of recommendations show top-converting products, while $\epsilon = 0.20$ explores random fresh items from diverse categories to collect exploratory interaction data.

### 5.2. New Item Cold-Start Strategy
1. **Zero-Delay Embedding Generation**:
   - When a merchant saves a new product in the admin dashboard, an asynchronous task immediately computes $\mathbf{e}_{new}$ and inserts it into `product_embeddings`.
   - The product is immediately retrievable via `similar-items` and semantic search.
2. **Fold-In Projection into Collaborative Latent Space**:
   - Since the new item has no entries in the ALS interaction matrix, its collaborative factor $\mathbf{y}_{new}$ is approximated via its $K$-nearest semantic neighbors:
   $$\mathbf{y}_{new} \approx \sum_{j \in \text{KNN}(new)} \frac{\text{sim}(\mathbf{e}_{new}, \mathbf{e}_j)}{\sum \text{sim}} \mathbf{y}_j$$
3. **Exploration Boost**:
   - New items receive a temporary artificial popularity multiplier ($+15\%$ boost to $S_{POP}$) during their first 72 hours or until they reach 50 impressions.

## 6. Production Python Interfaces & Implementation Architecture

The core engine is encapsulated in `apps/api/recsys/engine.py`. Below is the complete, high-performance implementation interface:

```python
"""
Core Hybrid Recommendation Engine Implementation
Handles retrieval, normalization, switching-weighted scoring, and MMR diversification.
"""

from typing import List, Dict, Optional, Tuple
import numpy as np
import scipy.sparse as sp
from pydantic import BaseModel
import asyncpg


class RecommendationCandidate(BaseModel):
    product_id: str
    cf_score: float = 0.0
    cbf_score: float = 0.0
    pop_score: float = 0.0
    final_score: float = 0.0
    category_id: str
    embedding: Optional[List[float]] = None


class HybridRecommenderEngine:
    def __init__(
        self,
        db_pool: asyncpg.Pool,
        als_user_factors: Optional[np.ndarray] = None,
        als_item_factors: Optional[np.ndarray] = None,
        user_id_map: Optional[Dict[str, int]] = None,
        item_id_map: Optional[Dict[str, int]] = None,
    ):
        self.db = db_pool
        self.user_factors = als_user_factors
        self.item_factors = als_item_factors
        self.user_id_map = user_id_map or {}
        self.item_id_map = item_id_map or {}
        self.reverse_item_map = {v: k for k, v in self.item_id_map.items()}

    def _normalize_scores(self, scores: np.ndarray) -> np.ndarray:
        """Min-max normalization with epsilon guard."""
        if len(scores) == 0:
            return scores
        s_min, s_max = np.min(scores), np.max(scores)
        if s_max - s_min < 1e-6:
            return np.ones_like(scores) * 0.5
        return (scores - s_min) / (s_max - s_min + 1e-6)

    def _calculate_weights(self, interaction_count: int) -> Tuple[float, float, float]:
        """Switching weight policy based on user interaction depth."""
        if interaction_count == 0:
            return 0.00, 0.70, 0.30  # w_cf, w_cbf, w_pop
        elif interaction_count < 5:
            return 0.25, 0.55, 0.20
        else:
            return 0.55, 0.35, 0.10

    async def retrieve_semantic_candidates(
        self, user_vector: List[float], limit: int = 50
    ) -> List[Dict]:
        """Retrieve top-K semantic nearest neighbors via pgvector HNSW."""
        vec_str = "[" + ",".join(f"{x:.6f}" for x in user_vector) + "]"
        query = """
            SELECT 
                pe.product_id::text,
                p.category_id::text,
                (1.0 - (pe.embedding <=> $1::vector)) AS cbf_score,
                pe.embedding::text AS raw_embedding
            FROM product_embeddings pe
            JOIN products p ON p.id = pe.product_id
            WHERE p.status = 'ACTIVE' AND p.stock_quantity > 0
            ORDER BY pe.embedding <=> $1::vector ASC
            LIMIT $2;
        """
        rows = await self.db.fetch(query, vec_str, limit)
        results = []
        for r in rows:
            emb = [float(x) for x in r["raw_embedding"].strip("[]").split(",")]
            results.append({
                "product_id": r["product_id"],
                "category_id": r["category_id"],
                "cbf_score": float(r["cbf_score"]),
                "embedding": emb,
            })
        return results

    def retrieve_collaborative_candidates(
        self, user_uuid: str, limit: int = 50
    ) -> List[Dict]:
        """Compute top-K collaborative scores using ALS factor dot products."""
        if user_uuid not in self.user_id_map or self.user_factors is None:
            return []
        
        u_idx = self.user_id_map[user_uuid]
        u_vec = self.user_factors[u_idx]  # Shape: (d,)
        
        # Batch dot product against all item latent factors: (M, d) x (d,) -> (M,)
        raw_scores = np.dot(self.item_factors, u_vec)
        top_indices = np.argpartition(raw_scores, -limit)[-limit:]
        top_sorted = top_indices[np.argsort(-raw_scores[top_indices])]
        
        results = []
        for idx in top_sorted:
            item_id = self.reverse_item_map.get(idx)
            if item_id:
                results.append({
                    "product_id": item_id,
                    "cf_score": float(raw_scores[idx]),
                })
        return results

    def apply_mmr_diversity(
        self,
        candidates: List[RecommendationCandidate],
        top_k: int = 10,
        lambda_param: float = 0.70,
    ) -> List[RecommendationCandidate]:
        """Apply Maximal Marginal Relevance to diversify recommendation output."""
        if len(candidates) <= top_k:
            return candidates

        selected: List[RecommendationCandidate] = []
        unselected = candidates.copy()

        # Step 1: Select highest ranked candidate
        first_pick = max(unselected, key=lambda c: c.final_score)
        selected.append(first_pick)
        unselected.remove(first_pick)

        # Step 2: Iteratively select items that maximize MMR equation
        while len(selected) < top_k and unselected:
            best_mmr_score = -float("inf")
            best_candidate = None

            for cand in unselected:
                if cand.embedding is None:
                    sim_to_selected = 0.0
                else:
                    cand_vec = np.array(cand.embedding)
                    sims = [
                        np.dot(cand_vec, np.array(s.embedding))
                        for s in selected if s.embedding is not None
                    ]
                    sim_to_selected = max(sims) if sims else 0.0

                mmr_val = (lambda_param * cand.final_score) - ((1.0 - lambda_param) * sim_to_selected)

                if mmr_val > best_mmr_score:
                    best_mmr_score = mmr_val
                    best_candidate = cand

            if best_candidate:
                selected.append(best_candidate)
                unselected.remove(best_candidate)
            else:
                break

        return selected

    async def get_personalized_recommendations(
        self,
        user_uuid: str,
        user_vector: Optional[List[float]],
        interaction_count: int,
        k: int = 10,
    ) -> List[RecommendationCandidate]:
        """
        Full Execution Pipeline:
        1. Multi-source Retrieval
        2. Score Normalization & Weight Blending
        3. MMR Reranking & Diversity
        """
        # Fallback if no user vector: retrieve trending items
        if user_vector is None or len(user_vector) == 0:
            return await self.get_trending_fallback(limit=k)

        # 1. Parallel candidate generation
        cbf_candidates = await self.retrieve_semantic_candidates(user_vector, limit=50)
        cf_candidates = self.retrieve_collaborative_candidates(user_uuid, limit=50)

        # Merge candidate dictionary
        candidate_dict: Dict[str, RecommendationCandidate] = {}

        for item in cbf_candidates:
            pid = item["product_id"]
            candidate_dict[pid] = RecommendationCandidate(
                product_id=pid,
                cbf_score=item["cbf_score"],
                category_id=item["category_id"],
                embedding=item["embedding"],
            )

        for item in cf_candidates:
            pid = item["product_id"]
            if pid in candidate_dict:
                candidate_dict[pid].cf_score = item["cf_score"]
            else:
                candidate_dict[pid] = RecommendationCandidate(
                    product_id=pid,
                    cf_score=item["cf_score"],
                    category_id="",
                )

        candidate_list = list(candidate_dict.values())
        if not candidate_list:
            return await self.get_trending_fallback(limit=k)

        # 2. Extract score vectors and normalize
        cf_arr = np.array([c.cf_score for c in candidate_list])
        cbf_arr = np.array([c.cbf_score for c in candidate_list])

        norm_cf = self._normalize_scores(cf_arr)
        norm_cbf = self._normalize_scores(cbf_arr)

        w_cf, w_cbf, w_pop = self._calculate_weights(interaction_count)

        for i, cand in enumerate(candidate_list):
            cand.final_score = (w_cf * norm_cf[i]) + (w_cbf * norm_cbf[i])

        # Sort descending by preliminary blended score
        candidate_list.sort(key=lambda x: x.final_score, reverse=True)

        # 3. Apply MMR Diversity filter
        final_recommendations = self.apply_mmr_diversity(candidate_list, top_k=k)
        return final_recommendations

    async def get_trending_fallback(self, limit: int = 10) -> List[RecommendationCandidate]:
        """Rule-based trending fallback when user history is zero."""
        query = """
            SELECT p.id::text, p.category_id::text, p.rating_avg
            FROM products p
            WHERE p.status = 'ACTIVE' AND p.stock_quantity > 0
            ORDER BY p.rating_count DESC, p.rating_avg DESC
            LIMIT $1;
        """
        rows = await self.db.fetch(query, limit)
        return [
            RecommendationCandidate(
                product_id=r["id"],
                final_score=float(r["rating_avg"]) / 5.0,
                category_id=r["category_id"],
            )
            for r in rows
        ]
```
